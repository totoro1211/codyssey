# 미션 2 기록

- 사용한 AI 이름 / 주요 대화 캡처 파일명:
  - Codyssey 학습 네이토의 GPT-5.5 / 학습 튜터를 사용했다. 원인을 먼저 질문하고 브라우저에서 확인한 뒤, 같은 대화에서 해당 문제만 수정해 달라고 요청했다.
  - 주요 대화 캡처: `대화캡처/원인_질문.jpg`, `대화캡처/원인_설명.jpeg`, `대화캡처/원인_확인방법.jpeg`, `대화캡처/수정_요청.jpeg`, `대화캡처/수정_설명.jpeg`, `대화캡처/수정_코드.jpeg`.
  - 직접 확인한 브라우저 검사 화면: `대화캡처/원인_브라우저확인.png`.
  - 보조 AI의 좁은 화면 확인 증빙: `대화캡처/화면폭_확인.png`.

- 좁혀서 적은 한 문장:
  - 수정 전 시험한 영화 제목 10개 중 띄어쓰기가 있는 4개만 클릭과 끌어 놓기 모두 S칸으로 옮겨지지 않고 미분류에 남으며, 띄어쓰기가 없는 6개는 옮겨진다.

- 좁히려고 해 본 것과 결과:
  - 제공된 `영화_수정전.html`은 고치지 않고 보관했다. 브라우저에서 ‘처음으로’를 눌러 기본 영화 8개로 시작한 뒤, 각 카드를 클릭하고 S 등급 글자를 눌렀다.
  - 기본 영화 8개의 클릭 이동을 확인하고, 초기화 후 같은 행동을 한 번 더 해 보니 같은 5개는 이동하고 같은 3개는 미분류에 남았다.
  - 끌어 놓기로도 8개를 확인했는데 성공한 영화와 실패한 영화가 클릭할 때와 같았다.
  - 실패한 제목에 띄어쓰기가 있다는 공통점을 찾았다. 이를 확인하려고 같은 글자에 띄어쓰기만 다르게 한 ‘어바웃타임’과 ‘어바웃 타임’을 추가했다. 클릭과 끌어 놓기 모두 붙여 쓴 제목만 이동했다.
  - 관찰 내용을 기획서 및 수정 전 HTML과 함께 AI에게 전달하고, 아직 수정하지 말고 원인과 브라우저에서 확인하는 방법부터 설명해 달라고 요청했다.

- AI가 말한 원인과, 그 설명을 직접 확인한 결과:
  - AI는 영화 카드를 만드는 HTML 문자열에서 `data-id` 값에 따옴표가 없어, 브라우저가 띄어쓰기 앞까지만 내부 이름표로 읽는다고 설명했다. 이동할 때 이 잘린 이름표로 영화를 찾으므로, 전체 제목이 저장된 목록에서 해당 영화를 찾지 못해 이동이 멈춘다는 설명이었다.
  - 브라우저의 ‘검사’ 기능으로 확인했다. 화면에 보이는 제목은 ‘센과 치히로의 행방불명’ 전체였지만 내부 이름표는 `data-id="센과"`로 잘려 있었다. 같은 검사 화면에서 ‘어벤져스: 엔드게임’은 `data-id="어벤져스:"`, ‘토이 스토리’는 `data-id="토이"`로 표시됐다.
  - 정상적으로 이동하는 ‘기생충’도 비교했다. 이 카드는 `data-id="기생충"`으로 전체 이름이 들어 있었다. 문제 카드와 정상 카드의 차이가 AI의 설명과 일치했다.
  - 확인 결과를 같은 AI에게 알려 주고, 다른 화면과 기능은 유지하면서 이 문제만 고쳐 달라고 요청했다. 반환된 전체 HTML을 원본과 다른 이름인 `영화_수정1.html`로 저장했다.

### 제출 전 추가 점검

- 보조 AI가 Chrome의 반응형 화면에서 수정본의 화면 폭을 375 CSS 픽셀로 설정해 확인했다. 제목·입력칸·추가 및 처음으로 버튼·S/A/B/C칸·미분류 카드와 안내문이 오른쪽으로 잘리지 않고 표시되었다. 실제 전체 페이지 캡처를 `대화캡처/화면폭_확인.png`로 보관했다. 이 캡처는 별도 브라우저 확인 당시의 배치이며, 학습자가 직접 확인한 재열기·초기화 결과는 위 표에 따로 기록했다.
- 수정본은 HTML·CSS·JavaScript가 한 파일에 들어 있고, 외부 리소스나 서버·로그인을 요구하는 코드가 없다. 브라우저에서 로컬 파일로 열리는 것을 확인했다.

직접 확인한 동작 결과는 위와 같다. 보조 AI는 원본과 수정본 전체 코드를 대조해 카드 생성 부분만 바뀌었음을 확인했고(파일 끝 줄바꿈 차이 제외), JavaScript 문법 검사도 수행했다. 원본 HTML은 변경하지 않았다.

코랩 세션 질문지는 선택 사항으로 작성하지 않았다. GitHub 등록과 동료평가 PASS 여부는 이 기록 작성 시점에 확인되지 않았다.
