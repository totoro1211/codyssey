# 1-3 동료평가 · 다른 사람의 페이지를 써 보고 의견 주기

**내가 한 일** — 민수 님의 영화 페이지를 직접 써 본 뒤, 제공된 AI와 동료의 의견이 맞는지 확인했다. 받아들일 의견, 잠시 보류할 의견, 더 물어볼 의견을 골라 피드백을 썼다.

## 옆에 열어 둘 것

- **제출한 글** — GitHub에서 `피드백.md`와 `미션3_기록.md`를 열어 둔다. `피드백.md`는 민수 님께 드리는 글이고, `미션3_기록.md`에는 받은 의견별로 내가 해 본 결과와 판단이 있다. [GitHub 1-3](https://github.com/totoro1211/codyssey/tree/main/1-3)
- **시연 화면** — 민수 님의 샘플 HTML을 Chrome에서 연다. 제공된 샘플 `민수_영화티어리스트.html`

## 이렇게 말하고 보여 주기

> “먼저 민수 님의 파일을 직접 써 보고 나서 받은 의견과 비교했어요. 등급 칸 색이 달라 구분하기 좋았고, 영화를 옮기면 몇 편을 분류했는지 알려 주는 점도 편했어요. 가장 먼저 고치면 좋을 점은 저장이에요.”

1. 화면에서 **기생충을 A칸으로 옮기고 인사이드 아웃을 추가한다.** “기획서에는 다시 열어도 이렇게 정리한 내용이 남아야 한다고 적혀 있어요.”
2. **‘처음으로’를 누르지 않고**, 같은 Chrome에서 샘플 파일을 닫았다 다시 연다. “처음 영화 8편으로 돌아왔어요. 그래서 다시 열 때 저장한 배치를 불러오도록 제안했어요.”
3. `피드백.md`의 첫 번째 항목을 가리킨다. “제가 한 행동, 기획서의 약속, 바꾸면 좋을 점을 순서대로 적었어요.”

**질문을 받으면**

- **받은 의견을 그대로 다 받아들였어요?** “직접 확인했어요. ‘처음으로’를 눌러도 추가한 영화가 안 지워진다는 의견은 제가 눌러 보니 지워져서 보류했어요.”
- **되묻기는 언제 골랐어요?** “‘휴대폰에서 불편했다’처럼 어느 화면에서 뭐가 불편했는지 알 수 없을 때, 그걸 더 알려 달라고 질문을 적었어요.”
- **다른 개선점도 있어요?** “컴퓨터 창을 좁히니 오른쪽이 잘렸고, 공백만 넣으면 빈 카드가 생겼어요. 공백 문제는 쓰다가 느낀 불편으로 적었어요.”
